## Token rules (audited WCAG AA, 2026-07-29 — do not regress)
- Always bind Figma variables / use CSS custom properties; never hardcode hex when a token exists
- Readable text: `color/text/muted` and `secondary` = slate/600 (4.5:1). **slate/500 is decorative only**
- Status colors: **600 = fills/badges, 700 = text** (`warn/err/info-700` exist for this)
- Input boundaries: `color/border/strong` (slate/450, 3.3:1). `border/default` (slate/300) only for cards/dividers
- Champagne only on Premium/Off-Market; text on `bg/premium` uses `text/premium-accent` (champagne/100), CTAs use champagne/800 with white label
- Touch targets: buttons/inputs/pagination 44px; checkbox/radio rows min 24px
- Text styles (13): Display/XL, Heading/H1–H3, Body/Default, Body/Small, Body/Small Strong, Caption/Default, UI/Button, UI/Label, UI/Badge, UI/Price, Overline — the DS typography section lists each style's size/line-height/weight/tracking spec
- **Typography readability rules (EU/WCAG, 2026-07-29)**: body-size copy keeps a ≥1.5 line height — theme tokens in `frontend/src/app/index.css` set `--text-sm--line-height: 1.5` and `--text-xs--line-height: 1.45`, so never re-tighten with `leading-snug`/`leading-none` on multi-line copy (single-line UI chrome centers via flex + `min-h`, so it's unaffected). `h1/h2/h3` get `letter-spacing: -0.015em` in `@layer base` (Jakarta extrabold runs loose at display sizes) — don't add per-heading `tracking-*`. **11px (`text-[11px]`) is the hard content floor** and only for short bold single tokens (badges, overlines, count bubbles, "Cover" tags, chart tooltips); multi-word sentences use `text-xs` minimum; `text-[10px]` is banned for content. Long-form copy stays ≤80ch (`max-w-*` prose blocks) with `leading-relaxed`. Every screen must survive the WCAG 1.4.12 text-spacing override (line-height 1.5em, letter-spacing 0.12em, word-spacing 0.16em) without clipping — text containers use `min-h`, never fixed heights; `tools/hotspot/shot-wcag1412.mjs` screenshots home/search/exposé/register with the override injected
- **9-locale typography pass (2026-07-30)**: `@layer base` in `frontend/src/app/index.css` sets `text-wrap: balance` on `h1/h2/h3` (DE/PT/NL headings run ~30% longer — two-liners stay even) and pulls link underline metrics from the font (`text-underline-position: from-font; text-decoration-thickness: from-font`). Key multi-line descriptions (hero sub, home band subs, EmptyState body) use `text-pretty`. Long-form prose (CMS/legal body, exposé description) gets `hyphens-auto` — `html lang` follows the locale so German compounds hyphenate — plus `break-words` for unhyphenatable tokens (emails, URLs, register IDs); user-generated text blocks (inquiry blockquote) always get `break-words`. Legal/CMS prose is capped at `max-w-2xl` (~60–75ch) and its `h1` steps down to `text-2xl sm:text-3xl` ("Datenschutzerklärung" alone overflows 320px at 3xl). **Inputs render 16px on mobile**: every text input/select visible below `sm` uses `text-base sm:text-sm` (kit `control` in `Field.tsx` + ad-hoc inputs) so iOS Safari never zooms — apply this to any new input. Units/prefixes join with `\u00A0`: `86 m²` in PropertyFacts, the `≈` CZK/PLN estimate prefix and the rent `/ mo` suffix in `format.ts`. Truncated values not visible in full elsewhere carry `title` tooltips (agent listings/inquiries/dashboard, map preview card, CRM credentials). `Button` no longer sets `select-none`. Sweeps: `tools/hotspot/overflow-public.mjs` (public routes, DE+NL, 320–768px) and `overflow-matrix.mjs` (agent panel) both pass clean
- **Web fonts ship every weight actually used** (2026-07-29): Inter + Plus Jakarta Sans load as *variable* fonts (`wght@400..800` / `500..800` in `frontend/index.html`) and `body` sets `font-synthesis: none` — `font-extrabold` (800) on prices/stats previously fell back to the closest loaded face (700), which made text render uneven next to true-800 display headings. If a new weight class is introduced, extend the Google Fonts range first
- **Prices are plain `Intl` text** (`fmtPrice`) — the € stays a text glyph everywhere. A Phosphor `CurrencyEur` icon-in-price variant was tried (2026-07-29) and rejected as looking worse; don't reintroduce it
- Effects: Elevation/sm|md|lg, Focus/ring — every interactive keeps a visible focus state
- **Radius rule (2026-07-29): full radius is reserved for Badges & status** — the Badge kit, count bubbles, progress meters, step dots — plus functional circles (spinner, toggle knob, map radius ring, avatars). Every interactive element (buttons, links, nav items, filter pills, chips, Seg controls, icon buttons, CTAs) uses `rounded-lg`; containers use `rounded-xl`/`2xl`; map price markers `rounded-md`. Never pill-shape UI controls

## EU compliance (binding on every screen)
- Cookie banner: Accept all / Reject non-essential / Manage preferences at equal size (44px)
- GDPR consent: checkboxes unchecked by default, mandatory, submit disabled until ticked; policy phrases underlined as links
- 9 languages (DE EN FR ES PT NL CS PL SK); design with ~30% text-expansion headroom; never fix widths to English
- Bind UI strings to `string/*` Locale variables where practical (124 exist; EN-only mode — Starter plan blocks addMode)
- **Frontend i18n (full-page switch, 2026-07-29)**: locale-prefixed URLs (`/de/…`) are the single source of truth — `switchLocale` swaps the prefix and keeps path + query, so changing the language in the header selector or footer select re-renders the *whole* page and updates `<html lang>`. **All 9 locales are fully translated (2026-07-30)**: ~784 keys each with verified 1:1 key parity against EN (`tools/hotspot/i18n-parity.mjs`); EN + DE live inline in `frontend/src/shared/i18n/dictionaries.ts`, FR/ES/PT/NL/CS/PL/SK in `frontend/src/shared/i18n/locales/*.ts` — add every new key to all nine files (EN fallback is a safety net, not a crutch). `t(key, vars)` supports `{placeholder}` interpolation — never concatenate sentence fragments (German word order differs, e.g. "Alle {n} Fotos anzeigen"). Enum-like data is translated via key namespaces `cat.*` / `kind.*` / `amen.*`, and every workflow status renders through `StatusBadge` + `status.*` keys — never raw status strings. Never `.toLowerCase()` a translated noun (German capitalization); format dates via `fmtDate`/`fmtDateTime(iso, locale)` and always pass `locale` to `toLocaleString`. Listing titles/descriptions stay source-language (AI exposé pipeline translates them later). Brand terms never translate: REVALO24, Off-Market, Top, OpenImmo, Stripe
- Light theme only; `prefers-reduced-motion` respected in code

## Page design rules
- **Page screens = Frames** composed of DS component instances. Only reusable chrome (Top Nav, Footer) and atoms/patterns are Components
- Desktop 1280 roots (primary design); large-desktop QA at 1440 (`max-w-shell` / 90rem in code). Auto-layout everywhere; FILL width children; name every frame. Property card grids stay 3-col at `lg`, 4-col at `2xl` only — do not reintroduce 4-col at `lg`
- Never fake overlap with negative `itemSpacing`; prefer `clipsContent = false` except intentional media wells
- Prefer real Input/Button/Chip/Card instances over dashed placeholders; placeholders only for map/photo/CMS blocks
- Card grids sized so WRAP yields 3×2, not one overflowing row
- **Radius = segmented snap control** (5/10/25/50 km pills, DS §13) — the slider was retired 2026-07-29; use `.seg` everywhere radius or Buy/Rent toggles appear
- Search/results follow the Zillow pattern: sticky filter bar with dropdown pills (live apply) on desktop, bottom sheet on mobile; map view is a full-height split (map + card panel of standard PropertyCards, hover syncs the marker)
- **List & map are one search**: `/properties` and `/map` share the URL query string (`useSearchFilters` + `FilterBar` in `features/search/FilterBar.tsx`); view switching happens via `FloatingViewSwitch` — a fixed bottom-center navy List|Map segmented control (rounded-xl shell, rounded-lg segments) that carries the query. On the mobile list view a Sort segment joins it (bottom sheet); the header sort select is desktop-only
- Property cards show key facts as the `PropertyFacts` icon row — **exactly three facts** (Duotone Ruler/Door/Bathtub = area/rooms/baths, action blue, tabular values), never plain-text meta strings. Rooms (not beds) is the EU headline figure; the full fact set lives only in the exposé Key facts grid. Card grids are **3 columns at lg, 4 at 2xl** (same scale on home featured and search — do not use 4-col at `lg`; that read as crowded)
- **Energy class uses the official EU EPC ladder** (`features/property/EnergyClass.tsx`, added 2026-07-29): fixed label colors A+ `#00843D` → H `#B81C22` with dark text on the yellow C–E midtones; arrow-shaped `EnergyClassBadge` (sm on cards — EPBD Art. 12 requires the class in ads — md in exposé Key facts) and the full `EnergyScale` ladder with marker in an "Energy performance" block on the exposé. On cards the badge anchors to the **right of the price row** (`justify-between`), never inline after the PropertyFacts icons — there it reads as a fifth fact and wraps raggedly. Badge letters are **Inter (`font-sans`) extrabold, 12px minimum, h-6 sm / h-7 md** — the display face goes muddy below ~12px, and the arrow clip eats ~0.5em of right padding, so never shrink these. Never restyle these colors with theme tokens
- Exposé Key facts render duotone icons per fact (Ruler/Tree/Door/Bed/Bathtub/Stairs/CalendarBlank/Lightning, action blue) — same icon language as `PropertyFacts`
- **Top nav** (redesign 2026-07-29): rounded-lg links with query-aware active states (Buy vs Rent share `/properties` and differ only in `?type=`, so match on the param, not the path); sticky header swaps border for elevation-md shadow after 8px scroll; auth CTAs are rounded-lg (Register = filled action); drawer has a logo header, duotone icons per link and a signed-in identity card on mobile. **Mobile shows the logo mark only** (`<Logo compact />` hides the wordmark below `sm`; keep `aria-label="REVALO24 home"` on the link) — the hotspot test showed the full logo stealing first-view attention on every mobile page. Footer, drawer and agent sidebar keep the full logo

- Favorites are auth-gated: guests tapping the heart get an info toast and are routed to login (`useFavorites` in `features/account`)
- Selects never show the native browser arrow: `appearance-none` + Phosphor CaretDown in reserved right padding (kit `Select` and any ad-hoc select)

Corollary (2026-07-30): a `grid` that only declares columns at `sm:`/`xl:` gets an implicit *auto* track (min-content floor) at the base breakpoint — **always write `grid-cols-1` explicitly** (Tailwind's `grid-cols-*` compiles to `minmax(0,1fr)` tracks, which is why desktop never showed the bug). ## Visual hotspot test (predicted attention)
- Local attention-heatmap pipeline in `tools/hotspot/` (kept out of `frontend/` on purpose): `capture.mjs` screenshots the first viewport of the 6 key conversion pages (home, search list, map, exposé, off-market, agents) at 1440×900 + 390×844 and exports conversion-target bounding boxes; `hotspot.py` computes a saliency map (OpenCV spectral-residual + fine-grained + center-view prior; auto-upgrades to DeepGaze IIE if torch is importable), renders `*-heat.png` overlays and writes `output/report.md`
- Run with the dev server up: `cd tools/hotspot && npm install && npm run setup` once, then `npm run hotspot`. Output is gitignored
- Reading scores: `lift` = attention share ÷ area share; <1.0 flags COLD. Known intentional colds: the Save-search pill (deliberately a quiet outline per the saved-searches rule) and very large boxes (a card filling 40% of a mobile viewport dilutes its own lift). A cold *primary* CTA (Search, Contact agent, Register/plan CTAs) is a real defect — rerun after hero/CTA changes to catch regressions
